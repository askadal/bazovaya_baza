# Базовая база МАФ

Каталог с серверным редактором владельца городского, детского и спортивного оборудования. Данные на 18–20 ноября 2026 года.

## Публикация на GitHub Pages

Распакуйте весь архив в корень локальной копии репозитория. На одном уровне
должны лежать `index.html`, `README.md`, `dist`, `scripts` и `.github`.
Отправьте распакованные файлы в ветку `main`. Если GitHub Pages уже публикует
`main` и папку `/(root)`, он автоматически откроет каталог по прежней ссылке.
Если источником выбран **GitHub Actions**, публикацию запускает сценарий
**Publish MAF catalog**. Его также можно запустить вручную в разделе **Actions**.

В сборку включены публичные правки последней версии Sites (версия 40).
GitHub Pages загружает категории, реакции и порядок выдачи из
`dist/client/catalog-state.json`. Значения закрытых оценок и сведения об
аккаунте владельца хранятся в Sites.

Архив фиксирует состояние каталога на момент переноса. Для входа через
`/owner` и дальнейшего серверного редактирования служит Cloudflare Worker.
Начальная база Worker создаётся при его отдельной настройке, описанной ниже.

## Размещение из GitHub

Храните исходники в репозитории GitHub, а каталог и сервер редактора запускайте вместе в Cloudflare Workers. Публичный адрес Worker открывает каталог. Редактор доступен аккаунту GitHub, чей числовой ID указан в настройках Worker. GitHub Pages размещает статические страницы, поэтому проекту нужен Worker.

1. Распакуйте архив, создайте пустой репозиторий на GitHub и откройте терминал в папке с файлами проекта. В команде `git remote add` подставьте адрес своего репозитория. Папка `dist/client` содержит готовый каталог и миниатюры. Она добавляется вместе с исходниками.

   ```powershell
   git init -b main
   git add .
   git commit -m "Add MAF catalog"
   git remote add origin https://github.com/YOUR-LOGIN/maf-catalog.git
   git push -u origin main
   ```

2. В корне проекта установите зависимости и подключите Wrangler к своему аккаунту Cloudflare.

   ```powershell
   npm ci
   npx wrangler login
   npx wrangler d1 create maf-catalog-github
   ```

3. Укажите выданный UUID базы вместо нулей в `d1_databases[0].database_id` файла `wrangler.jsonc`. Примените миграции и опубликуйте Worker. Команда вернёт адрес `https://…workers.dev`, если используется стандартный домен.

   ```powershell
   npx wrangler d1 migrations apply DB --remote
   npm run deploy
   ```

4. В GitHub откройте **Settings → Developer settings → OAuth Apps → New OAuth App**. В поле **Homepage URL** укажите HTTPS-адрес каталога, в поле **Authorization callback URL** укажите этот же адрес с окончанием `/api/auth/github/callback`. Скопируйте Client ID и создайте Client Secret. [Создание OAuth App](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app)
5. Получите числовой ID своего GitHub-аккаунта. Если GitHub CLI уже авторизован под вашим аккаунтом, используйте `gh api user --jq .id`. Иначе откройте `https://api.github.com/users/ВАШ_ЛОГИН` и скопируйте поле `id`. Внесите значения в Worker через команды ниже. Для `AUTH_ORIGIN` укажите HTTPS-адрес без завершающего слэша и пути.

   ```powershell
   npx wrangler secret put AUTH_ORIGIN
   npx wrangler secret put GITHUB_OWNER_ID
   npx wrangler secret put GITHUB_CLIENT_ID
   npx wrangler secret put GITHUB_CLIENT_SECRET
   ```

6. Откройте `/owner` на адресе каталога, нажмите «Войти через GitHub» и выберите свой аккаунт. После входа на главной появится круглая кнопка режима разработчика рядом с подборкой. Для выхода используйте кнопку на `/owner`. В приватном окне убедитесь, что каталог открывается без кнопки разработчика. Другой аккаунт получит отказ при попытке входа.

Секреты вводятся в Cloudflare. В архив включены карточки, изображения, экспорт PDF и Excel и миграции для новой базы D1. Снимок публичных правок Sites используется в сборке GitHub Pages. Локальные подборки хранятся в браузере. При каждом развёртывании сохраняйте привязку к созданной D1, чтобы правки переживали обновления кода.

## Покрытие

У Мегаполиса семь товарных страниц возвращают 404. У МАФ маркета недоступны девять страниц серий. У Новалура одна товарная страница недоступна, у Punto Group девять адресов карты. У Шелби 346 старых адресов карты возвращают 404: действующие ссылки сверены по страницам каталога. У Новых горизонтов включена только ветка уличного оборудования. У четырёх карточек Робинзона ссылки на фотографии возвращают 404; интерфейс показывает заглушку. Цветовые варианты Робинзона сохраняются как отдельные карточки, если производитель присваивает им собственную страницу/артикул.

## Запуск и сборка

Нужен Node.js 24+.

```
npm ci
npm test
npx wrangler d1 migrations apply DB --local
npm run dev
```

Источники задаются в data/sources.json, нормализованные карточки в data/<id>.json, отчёты покрытия в data/<id>-meta.json. Если меняете карточки, выполните `node scripts/build-catalog.mjs`, затем `node scripts/check-catalog-import.mjs`. Сборщики scripts/scrape-<id>.mjs используют публичные страницы и кеш. Большинство принимает абсолютный путь кеша первым аргументом. Перед повторным сбором проверьте правила и доступность источника. Для миниатюр используется sharp. Кенгуру при неполной TLS-цепочке Node использует стандартный Invoke-WebRequest Windows с проверкой сертификата.

## Интерфейс

Визуальное оформление построено по журнальному референсу: белое поле, крупный однострочный заголовок с выравниванием влево: всё название «БАЗОВАЯ БАЗА МАФ» набрано Manrope 600 одним цветом, общая сетка карточек с тонкими линиями и компактные контурные кнопки разделов и категорий, выровненные влево под названиями строк. Подпись также выровнена влево. Розовый и голубой акценты интерфейса сохранены. Тяжёлые рамки, прямоугольные залитые кнопки и контрастные тени заменены тонкими контурами. Окно объекта, таблица подборки и приватный редактор используют тот же шрифт и оформление.

Manrope хранится локально в dist/client/fonts/Manrope-Variable.ttf; лицензия SIL OFL — Manrope-OFL.txt. Вступительной заставки нет.


Производители по алфавиту, разделы и типы мебели — отдельные кнопки. Карточки добавляются при прокрутке, фильтры закреплены. Щелчок колёсиком или Ctrl/Cmd+щелчок по изображению/названию открывает карточку в новой вкладке; обычный щелчок открывает диалог. Параметр product в URL позволяет ссылаться на карточку. Подборка хранится в localStorage; PDF и XLSX содержат изображения, название, артикул, характеристики, количество.

Правила scripts/classify-requested.mjs объединяют площадки для собак в Другие изделия / Площадки для собак, велопарковки — в Велопарковки, детские навесы — в Навесы и веранды. Комплекс с навесом остаётся комплексом. Парклеты и подиумы в Других изделиях.

## Файлы сборки

Клиентские файлы в dist/client, Worker собирается в dist/server/index.js, настройки в wrangler.jsonc. Миниатюры для выгрузки в dist/client/thumbnails, индекс data/image-thumbnails.json. ExcelJS и pdfmake поставляются с лицензиями.

## Типы спортивного и музыкального оборудования

Спортивный раздел использует типы из scripts/classify-sports.mjs. Порядок отдаётся в categoryOrder каталога. Точное название снаряда имеет приоритет над широкими разделами производителей; спортивные кластеры и целые площадки отделены от отдельных комбинированных комплексов. Визуально проверенные соответствия с причинами сохраняются в data/category-overrides.json. Канатные игровые серии Кенгуру относятся к детским лазалкам и скалодромам.

Музыкальное оборудование выделяется по scripts/classify-music.mjs и data/music-classification.json: 143 проверенных инструмента и музыкально-игровых элемента. Декоративные панели, акустические переговорные устройства, домики и качели с дополнительной музыкой сохраняют основной тип.

Игровое спортивное оборудование предназначено только для спортивных игр (мяч, сетки, ворота, щиты, арены и принадлежности). Теннисные столы выделены отдельно. Самостоятельная категория баскетбольных щитов удалена. Воркаут-комплексы стоят перед Турниками; комбинированные снаряды не смешиваются с игровым инвентарём. Для неигровых спортивных конструкций предусмотрены отдельные группы комплексов, полос препятствий, баланса и координации, вспомогательных спортивных элементов.

## Заголовок

Всё название «БАЗОВАЯ БАЗА МАФ» набрано обычным текстом: Manrope 600, цвет #141414, без точки. Объёмного изображения и вращения нет. Подпись: «собрали все маф (ну почти) на одном сайте». Всё выровнено влево, заголовок остаётся одной строкой.

## Редактор владельца

Круглая кнопка с кодом рядом с подборкой включает карандаши и пять сердечек под каждой карточкой. Щелчок по сердечку немедленно сохраняет оценку без открытия объекта; повторный щелчок по текущей оценке снимает её. Старые значения 50 и ниже показываются как 0 сердечек, 51 — одно, 52 — два, 53 — три, 54 — четыре, 55 и выше — пять. Числа и сердечки видны только владельцу. Чем больше сердечек, тем выше объект в общей выдаче; при равной оценке сохраняется исходный порядок. Сортировка применяется до фильтров и подгрузки.

Карандаш раскрывает форму прямо под карточкой: раздел, категория, сердечки, сохранение и сброс. Повторный щелчок по карандашу или крестик сворачивает форму. После сохранения остаются уже подгруженные карточки; перенесённый в другой раздел объект исчезает из текущей выдачи. Оценка с карточки сохраняется отдельным PATCH-запросом и не меняет ручную категорию. Старые численные оценки не удаляются из D1: shared/catalog-rules.mjs переводит их в сердечки при чтении; новые оценки хранятся как 50 + число сердечек. Сброс возвращает исходную классификацию и ноль сердечек.

После прокрутки появляется кнопка «Наверх», возвращающая к заголовку и меню. При предпочтении уменьшенного движения используется мгновенная прокрутка. Рукоход, рукоход-змеевик и рукоход-молоток объединены в «Рукоходы», «Наклонная скамья» переименована в «Скамьи для упражнений». Общие правила применяются и к сборке каталога, и к старым ручным правкам в D1; прежние ссылки на категории распознаются по алиасам.

Правки хранятся в D1 (binding DB), схема db/schema.ts, миграции drizzle. После изменения схемы запустите `npm run db:generate` и примените миграции перед публикацией Worker. Обновления каталога сохраняют правки по стабильному id изделия. Конкурирующие изменения проверяются по ревизии, устаревшая запись получает 409.

Кнопка «Дно» рядом с сердечками сохраняет отдельный флаг bottom в D1. При сортировке по умолчанию такие объекты идут после всех обычных карточек, независимо от сердечек. Повторный щелчок снимает отметку и возвращает ранжирование по прежней оценке. Сердечки и ручная категория сохраняются; изменение сердечек или категории не снимает «Дно». Внутри группы «Дно» действует исходный порядок каталога. Общий сброс правок снимает и эту отметку. Управление и активная отметка доступны только владельцу.

Worker сверяет полученный от GitHub числовой ID с `GITHUB_OWNER_ID`. Сессия действует восемь часов и отзывается на сервере при выходе. JS редактора, численные оценки и изменение карточек доступны по действующей сессии. Публичное API передаёт категории, порядок идентификаторов и публичные реакции.

Локальный `npm run dev` использует отдельную D1. Для разработки без внешних аккаунтов `npm test` проверяет сценарии входа с тестовыми ответами GitHub. Проверку входа с реальным аккаунтом проведите после настройки HTTPS-адреса и OAuth App.

Выбранные модели Delo обновляются командой node scripts/scrape-delo.mjs [каталог кеша], затем пересобирается каталог. Фотографии сохранены в dist/client/images/delo, ссылки на оригиналы — в sourceImage. Размеры вручную сверены с габаритными схемами производителя; глубина табурета НРА не указана в схеме и не добавлена. Артикулы не опубликованы, поэтому sku остаётся пустым.

## Реакции авторов

Рядом с сортировкой расположены пять кнопок 😍 🌚 🙈 🫠 💅. Нажатие оставляет объекты с выбранной реакцией; несколько выбранных реакций работают через «или». Фильтрация сочетается с поиском, разделом, категорией, производителем и материалами, сохраняется в URL и снимается общим сбросом. Всплывающая подсказка: «по предвзятому мнению авторов».

Ставить и снимать реакции может только владелец в режиме разработчика — прямо на карточке и в редакторе. Остальные посетители видят уже поставленные реакции. Они хранятся в D1 отдельно от сердечек и «Дно» и не меняют порядок каталога. Миграция добавляет reaction_mask с нулевым значением; прежний simp читается как 😍 без перезаписи старых данных. Старые ссылки с simp=1 также открывают фильтр 😍. API симп поддерживается для ранее открытых вкладок; удаление правок снимает все реакции.

На кнопках и карточках используются локальные PNG Apple emoji из emoji-datasource-apple 16.0.0: вид одинаковый на разных ОС, внешние CDN не требуются. Источник и сведения о правах — images/reactions/SOURCE.txt. Кнопки имеют текстовые подписи для экранного диктора, видимый фокус и состояние нажатия.
